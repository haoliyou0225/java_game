# 双人钩子矿工游戏（JavaFX）

基于 Java 17 + JavaFX 17 的双人本地对战游戏，灵感来自「黄金矿工」。两位玩家各操控一套钩子，在倒计时内抓取物品（金块/钻石/石头/炸弹）累计分数，分高者获胜。

> **当前进度**：仅完成工程骨架与入口可运行 Demo（一个含按钮的窗口）。后续逐步实现各模块功能。

## 统一环境要求
| 项 | 版本 | 说明 |
| JDK | 17 或更高 | `maven.compiler.source/target=17` |
| Maven | 3.6+ | 构建与运行 |
| JavaFX | 17.0.13 | 通过 Maven 依赖自动下载，**无需单独安装 JavaFX SDK** |

环境验证：
java -version
mvn -version

## 操作说明（目标玩法，实现后生效）

| 玩家 | 抛出钩子 | 其他（可扩展） |
|---|---|---|
| 玩家 1 | `空格` | — |
| 玩家 2 | `回车` | — |

> 钩子在静止时会左右钟摆摆动，按键瞬间沿当前角度抛出。

## 模块分工与接口契约

### 成员 A：钩子物理模块（玩家 1 + 玩家 2 两套钩子）

**负责类**：`Hook`、`Rope`

**职责**
1. 钩子钟摆摆动物理（三角函数计算角度变化）
2. 钩子抛出、收回、绳索长度动态绘制
3. **钩子之间互相碰撞检测**：两个钩子相碰会互相弹开，不能互相抓取
4. 钩子与物品的碰撞判定（是否勾住物体）
5. 钩子状态机：`静止 → 摆动 → 抛出 → 收回 → 抓取中`

**对外接口**（供其他模块调用）
```java
// 检测与物品碰撞
CollisionResult checkCollisionWithItem(Item item);
// 检测与另一玩家钩子碰撞
boolean checkCollisionWithOtherHook(Hook other);
```

> 重点物理代码，**不直接操作物品内部逻辑，只调用物品接口**。

---

### 成员 B：物品多态体系（核心 OOP 得分模块）

**负责类**：抽象类 `Item`，子类 `Gold`、`Stone`、`Diamond`、`Bomb`

**职责**
1. 抽象父类定义通用属性：重量、分数、位置、大小、是否被抓取
2. 各子类重写行为：
   - `Stone`：重量大，回收慢
   - `Diamond`：高分，重量小
   - `Bomb`：抓取后爆炸，造成扣分
3. 物品拖拽物理：被钩子勾住后跟随钩子做拖拽运动，受重量影响回收速度
4. 物品之间简单碰撞（可选加分）；物品落地、爆炸逻辑

**对外接口**
```java
// 被钩子抓取时回调
void onGrab(Hook hook);
// 每帧更新位置（跟随钩子拖拽）
void updatePosition();
```

> 继承多态核心，**答辩重点讲**。成员 A 的钩子模块通过这两个接口操作物品，不修改 `Item` 内部字段。

---

### 成员 C：游戏管理器 + 关卡规则 + 双人游戏逻辑

**负责类**：`GameManager`、`Level`

**职责**
1. 全局游戏状态：开始 / 游玩 / 倒计时 / 结束
2. 双人独立计分系统：玩家 1 分数、玩家 2 分数、关卡目标分数
3. 关卡数据加载：每关生成哪些物品、物品位置
4. 游戏循环总调度：每帧调用 `Hook` 更新、`Item` 更新、碰撞检测
5. 胜负判定：倒计时结束比较两人分数，输出获胜者
6. 炸弹爆炸后的全局效果（扣分、清除物品）

> 游戏调度中枢，负责把 A、B 模块组装起来。**不写底层物理，只负责业务规则与状态管理**。

---

### 成员 D：UI 渲染、键盘输入、整合调试、文档

**负责类**：`GameUI`、`Menu`

**职责**
1. 键盘输入：玩家 1、玩家 2 两套按键监听（P1=空格抛钩子，P2=回车抛钩子）
2. 画布渲染：绘制背景、钩子绳索、所有物品、分数面板、倒计时、胜利失败弹窗
3. 游戏菜单：开始界面、选择关卡、结束界面
4. 项目整合：把 A/B/C 写好的模块拼在一起，处理 bug、做测试
5. 输出 UML 类图、时序图，编写报告，准备答辩演示

输入监听与渲染逻辑，同时负责项目整合。

## 模块依赖与数据流

```
                +-----------------------+
   键盘输入 ---->| 成员D: InputController |
                +-----------+-----------+
                            |
                            v
                +-----------------------+
                | 成员C: GameManager    |<--- 关卡/双人分数/倒计时
                |  (游戏循环总调度)      |
                +-----------+-----------+
                            |
              每帧调用 update() / 碰撞检测
                            |
            +---------------+---------------+
            |                               |
            v                               v
+-----------------------+       +-----------------------+
| 成员A: HookController | <---> | 成员B: ItemController |
|  (钟摆/抛出/收回)      |       |   (拖拽/爆炸/落地)    |
+-----------+-----------+       +-----------+-----------+
            |                               |
            v                               v
+-----------------------+       +-----------------------+
| Hook / Rope (model)   | call  | Item 及子类 (model)    |
| 状态机、角度、长度     |--onGrab-->| Gold/Stone/Diamond/Bomb
+-----------------------+       +-----------------------+
            |                               |
            +---------------+---------------+
                            |
                            v
                +-----------------------+
                | 成员D: GameUI 渲染     |
                +-----------------------+
```

**解耦要点**
- `Hook` 只调用 `Item.onGrab()` / `updatePosition()`，不修改物品内部字段
- `GameManager` 只调度各 Controller 的 `update()`，不写物理
- `GameUI` 只从 Model 读数据画图，不写业务

## Git 规范

- 分支：`main`（稳定） / `feat/<功能>` / `fix/<问题>` / `chore/<杂项>`
- 提交信息格式：`<type>(<scope>): <subject>`，如 `feat(hook): 实现钩子钟摆物理`
