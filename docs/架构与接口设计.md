## 1. 整体架构概述

本项目采用 MVC 分层架构，划分为 5 层：`config`配置层、`model`数据模型层、`controller`业务控制层、`view`视图层、`util`工具层。

核心原则：

1. **model 层纯数据模型，不引入任何 JavaFX 包，与界面完全解耦，便于逻辑单元测试**。
2. controller 层负责业务、物理、游戏调度，只能调用 model 对外公开接口，**严禁直接访问 model 私有成员变量**。
3. view 层只做数据读取与画面渲染，**不修改任何游戏业务数据**。
4. 所有常量集中放置在 config，禁止魔法数字散落在业务代码中。

## 2. 各分层职责说明

### config 配置层

>
> 包路径：`com.dz.hello.config`

- 存放全部游戏常量：窗口尺寸、倒计时时长、钩子摆动角速度、各类物品分数、重量、物理参数。
- 仅提供常量读取，不依赖其他业务模块，被其他所有层读取。

### model 数据模型层

>
> 包路径：`com.dz.hello.model`；实体子包：`com.dz.hello.model.entity`
> ⚠本层禁止 import javafx.* 相关包

- 存储游戏全部实体状态与数据：钩子、绳索、物品、关卡数据、双人游戏全局状态。
- 实体内部封装私有字段，对外只提供公开方法与 getter，不暴露内部属性。
- 只处理数据状态变更，不做界面渲染、不监听键盘输入。

类清单：

- `entity.Hook`：钩子实体、状态机、角度、绳索长度
- `entity.Rope`：绳索数据模型
- `entity.Item`：物品抽象父类
- `entity.Gold / Diamond / Stone / Bomb`：物品子类
- `GameData`：全局游戏状态（双玩家分数、倒计时、游戏阶段）
- `Level`：关卡数据，物品生成位置配置

### controller 业务控制层

>
> 包路径：`com.dz.hello.controller`

- 实现游戏业务逻辑、物理计算、输入分发、游戏总循环调度。
- 依赖 model、config、util；**不依赖 view 层**。

类清单：

- `HookController`：钩子摆动、抛出、收回物理逻辑
- `ItemController`：物品抓取、拖拽、爆炸、落地逻辑
- `GameManager`：**游戏总调度中枢**，主循环入口，每一帧驱动全游戏更新，胜负判定
- `InputController`：接收原始键盘事件，转换为游戏动作指令交给 GameManager

### view 视图层

>
> 包路径：`com.dz.hello.view`；组件子包：`com.dz.hello.view.component`

- 只负责读取 model 层数据完成画面绘制，不修改游戏业务状态。
- 依赖 model、config、util；不调用 controller 修改游戏数据。

类清单：

- `GameUI`：游戏画布渲染，绘制钩子、绳索、物品、HUD 分数倒计时
- `Menu`：开始菜单、游戏结束弹窗

### util 工具层

>
> 包路径：`com.dz.hello.util`

- 通用工具函数，供各层调用。
- `CollisionUtil`：碰撞检测工具
- `ResourceUtil`：图片、音频资源加载工具

## 3. 模块依赖与调用约束

✅允许调用

1. config：被所有层读取，不调用其他模块
2. model：无业务依赖，不调用 controller、view
3. controller：可以调用 model /config/util；**禁止调用 view**
4. view：可以读取 model /config/util；**禁止调用 controller 修改业务状态**
5. util：可被 model、controller、view 调用，不依赖业务模块

❌严格禁止

1. model 层 import 任何 JavaFX 类
2. 跨层直接访问对象 private 字段；状态修改必须调用对外公开方法
3. view 层修改 model 内部数据
4. model 反向调用 controller/view

### 4.1 Hook 钩子实体（model.entity.Hook，成员 A 实现）

 * 更新钩子摆动（摆动状态下每帧调用）

/**
 * 执行抛出动作：切换状态为抛出

/**
 * 执行收回动作：切换状态为收回
 */

 * 检测钩子与物品碰撞

// -------- 只读getter，供controller、view读取 --------

## 5. 架构风险与开发规范

1. **model 层禁止依赖 JavaFX**：如果引入 JavaFX，会导致数据逻辑无法脱离界面做单元测试。
2. 所有实体状态变更，**必须调用公开接口方法，禁止直接修改 private 成员**，多人协作避免状态不同步 bug。
3. 业务逻辑全部收敛在 model 与 controller，view 只负责绘制；UI 不能改变游戏逻辑。
4. 时间统一使用`deltaTime`帧间隔时间，不写死固定步长，保证不同帧率下游戏物理表现一致。
5. 枚举（钩子状态、游戏动作）统一放在 config 或者 model 包，不要散落各个类中。
6. 接口变更流程：文档先修改，小组对齐确认之后，再修改 Java 代码，禁止直接改代码而不更新本契约文档。
