#概要设计说明书

# 1 引言

## 1.1 编写目的

> 本文档为基于 JavaFX 实现的双人黄金矿工游戏的概要设计说明书，用于明确项目整体架构、分层设计、模块职责、核心流程与接口规范。本文档面向开发人员、课程设计评审人员，作为项目开发、维护、答辩与验收的依据。

本项目遵循 MVC 分层思想，划分为 controller 控制器、model 模型、util 工具、view 视图四层，实现视图、控制器、模型完全解耦，满足**“视图只绘制、控制器只调度、模型只负责数据与业务规则”**的分层开发规范。

## 1.2 项目背景

双人黄金矿工是经典休闲小游戏。核心玩法：钩子伸缩抓取地下物品，抓取黄金、钻石加分；抓取石头低分；抓取炸弹扣分爆炸；支持双人游戏、计分统计。

本项目采用 Java + JavaFX 技术开发。

- **Model 层纯 Java，无 JavaFX 依赖，只保存物品数据与状态；**
- View 层负责界面渲染，由小组其他成员开发；
- Controller 层负责事件调度、钩子控制、游戏帧循环。

## 1.3 运行环境

- 操作系统：Windows
- 开发环境：IntelliJ IDEA 
- 运行依赖：JDK11+、JavaFX SDK、Maven
- 项目架构：MVC 衍生四层架构：`controller`、`model`、`util`、`view`

## 1.4 术语与缩写

- MVC：Model‑View‑Controller，模型‑视图‑控制器分层架构
- Model：模型层，存储游戏物品数据、物品自身业务规则，纯 Java，不依赖界面
- Controller：控制层，接收用户输入、帧循环调度、调用模型接口，不做绘制
- View：视图层，JavaFX 界面渲染，只读取模型数据，不修改业务状态（其他组员实现）
- util：通用工具层，放置碰撞计算等通用静态工具类
- IHook：钩子对外接口，定义钩子对外提供的读取坐标、半径的方法

# 2 总体设计

## 2.1 设计目标

1. 实现双人黄金矿工核心 P0 需求：钩子抓取黄金、钻石、石头、炸弹；炸弹爆炸扣分；分数统计。
2. 严格分层解耦：**Model 层零 JavaFX 依赖，View 只渲染，Controller 只调度流程**。
3. 核心实体采用「接口 + 实现类」：钩子模块使用`IHook`接口 + `HookImpl`实现类。
4. 代码模块化、职责单一，无循环依赖，便于小组多人并行开发。
5. 游戏帧循环驱动，每一帧执行碰撞检测、物品状态更新、界面刷新。

## 2.2 整体架构设计

系统分为四层，单向依赖，禁止反向依赖：

1. **model 模型层（纯 Java）**：底层核心，存放所有游戏物品实体 (Item 及其子类)，只保存状态、执行业务方法，**完全不依赖 JavaFX、不依赖 View**。
2. **util 工具层**：通用工具，本例提供圆形碰撞检测工具`CollisionUtil`，供 Controller 调用。
3. **controller 控制层**：中层调度；包含钩子接口`IHook`与实现`HookImpl`、`GameController`游戏控制器；接收定时器帧事件，调用 model、util 的接口，**不绘制界面**。
4. **view 视图层（JavaFX）**：上层展示，读取 model 数据做画面渲染；**本模块由其他组员开发，本次提交不包含 view 源码**。

>
> 依赖方向：controller 可以调用 model、util；view 读取 model；**model 绝不依赖 view**。

## 2.4 整体业务流程

1. 程序 Main 入口启动，初始化 GameController，初始化地下各类物品对象、初始化钩子。
2. 启动游戏定时器帧循环。
3. 每一帧执行：
    1. GameController 获取钩子的坐标半径（调用 IHook 接口方法）。
    2. GameController 调用`CollisionUtil.circleCollision()`检测钩子与物品的圆形碰撞。
    3. 如果发生碰撞：调用`item.onGrab(hook)`，传入 IHook 钩子对象，修改物品抓取状态。
    4. 调用`item.updatePosition()`更新物品位置；炸弹如果被抓取可触发爆炸。
    5. 计分逻辑更新分数。
4. View 读取 model 中物品的 x、y、分数等状态，渲染画面。
5. 钩子收回 / 放出，重复帧循环逻辑。

# 3 分层模块详细设计

## 3.1 Model 模型层

>
> 设计约束：**无任何 JavaFX 导入，纯普通 Java 类，只做数据存储与物品自身业务，不绘图**。

### 3.1.1 Item 物品抽象父类

所有游戏物品的抽象父类，不能直接实例化。

- 存储属性：`protected double x,y; int scoreVal; double weight; boolean grabbed;`
- 抽象方法：
    - `onGrab(IHook hook)`：钩子抓取到物品瞬间调用，标记物品被抓取状态；参数为钩子接口对象。
    - `updatePosition()`：每一帧被调用，用于更新物品坐标；被抓取后跟随钩子移动；空实现骨架。
- getter 方法：`getX() getY() getScoreVal() getWeight() isGrabbed()`；只对外读，不提供 setter。

### 3.1.2 Gold 黄金，继承 Item

普通得分物品。

- 构造：`Gold(double x, double y)`，初始化坐标，固定属性：scoreVal=100，weight=1.0，grabbed=false。
- 重写`onGrab`：抓取后设置`grabbed=true`。
- 重写`updatePosition()`：空实现，预留跟随钩子移动逻辑。

### 3.1.3 Diamond 钻石，继承 Item

高分稀有物品。

- 构造：`Diamond(double x, double y)`；scoreVal=200，weight=1.2，grabbed=false。
- 重写`onGrab`：抓取设置 grabbed=true。
- `updatePosition()`空实现。

### 3.1.4 Stone 石头，继承 Item

低分、高重量障碍物。

- 构造：`Stone(double x, double y)`；scoreVal=10，weight=3.0，grabbed=false。
- 重写`onGrab`：抓取设置 grabbed=true。
- `updatePosition()`空实现。

### 3.1.5 Bomb 炸弹，继承 Item

负面物品，抓取后扣分，支持爆炸。

- 额外私有属性：`private boolean exploded`，标记炸弹是否爆炸。
- 构造：`Bomb(double x, double y)`；scoreVal=-150，weight=1.5，grabbed=false，exploded=false。
- 重写`onGrab`：抓取设置 grabbed=true。
- `updatePosition()`空实现。
- 独有方法：
    - `triggerExplode()`：触发爆炸，修改 exploded 状态。
    - `isExploded()`：返回爆炸状态，供控制器读取。

## 3.2 util 工具层

### 3.2.1 CollisionUtil 碰撞工具类

>
> final 工具类，私有构造，禁止 new 实例；全部静态方法。

- 静态方法：`circleCollision(x1,y1,r1,x2,y2,r2)`
- 功能：计算两个圆形是否发生碰撞；返回 true 代表碰撞发生，可以执行抓取逻辑。
- 实现原理：两圆心距离 ≤ 两圆半径之和。
- 调用方：GameController 每一帧调用该工具。

## 3.3 Controller 控制层（队友开发）

>

1. IHook 接口：提供`getX() getY() getRadius()`，向外暴露钩子坐标、头部半径。
2. HookImpl：实现 IHook，实现钩子伸缩、移动逻辑。
3. GameController：游戏主控制器，帧循环驱动；调用 CollisionUtil 做碰撞；调用 Item 的 onGrab、updatePosition；处理计分逻辑。

>
> 职责：接收定时器帧事件，调度 model 与 util；**Controller 不绘图，不写物品内部业务规则**。

## 3.4 View 视图层（队友开发）

>
> 无源码交付
> 设计约束：JavaFX 代码全部在此层；只读取 model 的 getter 获取物品坐标、分数；**绝不修改 model 内部状态**；负责画布渲染所有物品、钩子、分数 UI。

## 3.5 入口 Main 模块

负责各层对象组装、JavaFX 窗口初始化、定时器帧循环启动。是唯一可以同时操作 View、Controller、Model 的入口。

# 5 系统分层约束与规范

1. **Model 层零界面依赖：model 所有 Java 文件禁止导入 javafx.*，纯业务数据，可以脱离界面独立单元测试。**
2. util 工具层不依赖 View，只被 Controller 调用。
3. Controller 层只调度，不实现物品业务规则，不绘图。
4. View 层只读 Model 数据，不能调用 model 内部修改字段，只能调用公开 getter。
5. 依赖单向：Item 依赖`IHook`接口；**IHook 不引用 Item，无循环依赖**。
6. 类职责单一：CollisionUtil 只做碰撞；物品类只维护自身状态，不控制钩子逻辑。

# 6 系统运行机制

游戏采用**定时器帧刷新驱动机制**：

1. 定时器触发游戏帧 tick。
2. GameController 获取钩子信息，调用 CollisionUtil 检测钩子与各个物品碰撞。
3. 发生碰撞：调用`item.onGrab(hook)`修改物品抓取状态。
4. 遍历全部物品调用`item.updatePosition()`更新物品位置；炸弹可触发爆炸。
5. 计分逻辑更新游戏分数。
6. View 读取 model 中全部物品状态，刷新画面渲染。

# 7 功能总结

- ✅ 物品模型：黄金、钻石、石头、炸弹，各自分数、重量属性
- ✅ 抓取业务：onGrab 标记物品被抓取状态
- ✅ 炸弹爆炸状态管理
- ✅ CollisionUtil 圆形碰撞检测
- ✅ 严格分层：model 层无 JavaFX，单向依赖，无循环依赖
- ✅ 核心实体面向接口编程：钩子模块 IHook + HookImpl

>
> 说明：钩子运动、UI 渲染、完整计分逻辑，由小组其他成员完成。

# 8 扩展性说明

本架构预留扩展能力：

- 后续可以新增更多种类物品，直接继承 Item 抽象类，无需修改控制器、碰撞工具代码。
- 可以扩展物品特殊效果（抓取后加速、减速），在子类 onGrab 内扩展。
- 支持双人模式多钩子，控制器只需要传入不同 IHook 对象，model 层无需改动。
